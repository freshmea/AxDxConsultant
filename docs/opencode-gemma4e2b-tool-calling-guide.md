# OpenCode Tool Calling Guide For `gemma4:e4b`

이 문서는 OpenCode에서 `ollama/gemma4:e4b`를 사용할 때 도구 호출 정확도를 높이기 위한 운영 지침이다.

목표는 다음 두 가지다.

1. 도구가 필요한 작업에서 도구를 실제로 호출한다.
2. 도구 결과를 꾸며내지 않고, 필요한 경우 추가 도구를 연속 호출한다.

## Core Rule

도구가 필요한 작업은 추측하지 말고 반드시 도구를 호출한다.

- 최신 정보
- 현재 시점 정보
- 웹 검색
- 특정 URL 내용 확인
- 로컬 파일 검색
- 코드베이스 탐색
- 쉘 명령 실행
- 파일 수정

위 작업은 답을 바로 생성하지 말고 먼저 적절한 도구를 사용한다.

## Tool Selection Rules

### `websearch`

`websearch`는 인터넷에서 정보를 찾는 도구다.

다음 경우 반드시 `websearch`를 먼저 사용한다.

- 사용자가 최신 정보, 현재 정보, 오늘 기준 정보를 요청할 때
- 사용자가 "검색", "찾아봐", "웹에서", "인터넷에서"를 요청할 때
- 문서, 제품, 서비스, 라이브러리, 모델의 최신 상태를 확인해야 할 때

사용 규칙:

- 검색이 필요하면 답변을 바로 쓰지 말고 먼저 `websearch`를 호출한다.
- 검색 결과가 충분하지 않으면 검색어를 바꿔 한 번 더 호출한다.
- 검색 결과를 요약할 때는 출처 URL을 포함한다.
- 웹 검색 없이 최신 사실을 단정하지 않는다.

인자 규칙:

- `websearch`는 반드시 `query` 키를 포함해 호출한다.
- 잘못된 키 이름을 만들지 않는다.

예:

```json
{
  "query": "current president of France"
}
```

### `webfetch`

`webfetch`는 이미 알고 있는 URL의 내용을 읽는 도구다.

다음 경우 사용한다.

- `websearch` 결과에서 특정 문서를 자세히 읽어야 할 때
- 사용자가 URL을 직접 제공했을 때
- 공식 문서, API 문서, 블로그 글, 릴리스 노트를 확인해야 할 때

사용 규칙:

- 먼저 `websearch`로 찾고, 그다음 `webfetch`로 읽는다.
- 이미 정확한 URL이 있으면 바로 `webfetch`를 사용한다.
- 내용을 읽지 않고 URL 제목만 보고 결론을 내리지 않는다.

인자 규칙:

- `webfetch`는 반드시 URL 값을 포함해 호출한다.
- 도구 스키마에서 요구하는 URL 필드를 그대로 사용한다.

예:

```json
{
  "url": "https://example.com"
}
```

### `read`

로컬 파일 내용을 읽을 때 사용한다.

- 파일 경로를 이미 알고 있을 때
- 특정 파일 내용을 확인해야 할 때

### `glob`

파일 이름이나 경로 패턴으로 파일을 찾을 때 사용한다.

- 어디에 파일이 있는지 모를 때
- `*.md`, `*.py`, `src/**` 같은 패턴 탐색이 필요할 때

### `grep`

문자열, 심볼, 설정 키, 함수 이름을 찾을 때 사용한다.

- 코드나 문서에서 특정 텍스트를 검색할 때
- 설정 키나 함수 이름의 실제 위치를 찾아야 할 때

### `bash`

셸 명령이 필요한 경우 사용한다.

- 버전 확인
- 서버 상태 확인
- 패키지 설치
- 테스트 실행
- API 호출

명령을 추측 결과처럼 서술하지 말고 실제로 실행한다.

### `edit` / `write`

파일을 바꿔야 할 때만 사용한다.

- 수정 전에 `read`, `glob`, `grep` 등으로 충분히 확인한다.
- 사용자가 변경을 요청하지 않았으면 불필요한 수정은 하지 않는다.

## Mandatory Behavior For Search Tasks

검색 관련 요청에서는 아래 순서를 따른다.

1. 최신성 여부를 판단한다.
2. 최신성이 중요하면 `websearch`를 호출한다.
3. 필요한 경우 결과 URL을 `webfetch`로 읽는다.
4. 그 후에만 최종 답을 작성한다.

금지 사항:

- 웹 검색이 필요한 질문에 기억만으로 답하기
- 검색하지 않았는데 "현재", "최신", "오늘"이라고 단정하기
- 존재하지 않는 검색 결과를 만든 척하기

## Mandatory Behavior For Repository Tasks

코드나 문서 작업에서는 아래 순서를 따른다.

1. 위치를 모르면 `glob`
2. 텍스트 탐색은 `grep`
3. 내용 확인은 `read`
4. 필요 시 `bash`
5. 수정이 필요할 때만 `edit` 또는 `write`

금지 사항:

- 파일을 읽지 않고 내용을 아는 척하기
- 함수 위치를 확인하지 않고 추측으로 설명하기
- 최신 코드 상태를 보지 않고 수정안부터 제시하기

## Response Policy

도구를 호출한 뒤에는 다음 정책을 따른다.

- 도구 결과가 있으면 그 결과를 바탕으로 답한다.
- 결과가 부족하면 추가 도구를 다시 호출한다.
- 도구 실패 시 실패 사실을 짧게 설명하고 대안을 제시한다.
- 도구가 없거나 비활성이라면 그 사실을 명확히 말한다.

## Search-Specific Output Format

웹 검색이 포함된 답변은 가능하면 아래 형태를 따른다.

1. 한 줄 결론
2. 핵심 근거 1~3개
3. 출처 URL 1개 이상

예:

- 결론: 현재 X는 Y다.
- 근거: 공식 문서에서 Z를 명시한다.
- 출처: `https://...`

## Exact Tool Names

도구 이름은 아래 문자열을 정확히 사용한다.

- `websearch`
- `webfetch`
- `read`
- `glob`
- `grep`
- `bash`
- `edit`
- `write`

비슷한 이름을 임의로 만들지 않는다.

## Tool Argument Discipline

도구 이름만 맞는다고 충분하지 않다. 도구 호출 시 인자 키도 정확해야 한다.

- 도구를 호출하기 전에 필요한 필수 키를 확인한다.
- 추측한 키를 만들지 않는다.
- 특히 `websearch`는 `query` 키가 반드시 있어야 한다.
- 스키마 오류가 나면 같은 도구를 올바른 인자로 다시 호출한다.

## Model-Specific Reminder For `gemma4:e4b`

`gemma4:e4b`는 도구 호출 품질이 더 낫더라도 다음 원칙을 강하게 따른다.

- 도구가 필요하면 생각만 길게 하지 말고 빨리 도구를 호출한다.
- 한 번에 너무 많은 목표를 세우지 않는다.
- "먼저 찾고, 읽고, 그다음 답한다" 순서를 유지한다.
- 최신 정보, URL 확인, 코드 위치 확인은 항상 도구 우선이다.

## Single-Sentence Operating Rule

최신 정보는 `websearch`, 특정 URL은 `webfetch`, 로컬 탐색은 `glob`/`grep`/`read`, 실행은 `bash`, 수정은 `edit`/`write`를 먼저 사용하고 그 후에만 답변한다.
